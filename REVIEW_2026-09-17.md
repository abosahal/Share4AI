## نتائج مرتبة بالأولوية | Prioritized findings

### P1 — إعداد توزيع الذاكرة لا يصل إلى المحرك | Offload setting never reaches runtime
Evidence: provider/catalog.py:20, provider/provision.py:48, provider/app.py:115, provider/runtime.py:100.
يوصي الكتالوج بـ28 طبقة على GPU ويحفظها في installed.json، لكن start_local لا يمرر ngl، والمحرك يطلب 99 طبقة لكل GPU. بالتالي لا يُطبق مسار 27B المقصود لبطاقات الذاكرة المحدودة، وقد يفشل التشغيل بسبب الذاكرة. نجاح اختبار التوصية وحده لا يكشف هذا الخلل. هذا عائق تشغيل بعد التنزيل، وليس دليلًا على سبب توقف التنزيل في الصورة.
The catalog recommends 28 GPU layers and persists ngl, but start_local does not pass it and the adapter requests 99 layers for every GPU. The intended 27B RAM-offload path is not applied and can fail during allocation. Recommendation-only tests miss the boundary. This is a post-download startup defect, not proof of the screenshot's download failure.

### P1 — التحديث يرفض النماذج المثبتة سابقًا | Upgrade rejects previously installed models
Evidence: provider/catalog.json models; provider/provision.py:63.
حذف 4B و9B من الكتالوج يجعل verify_install يرفض تثبيتهما السابق. المستخدم الذي نجح لديه التطبيق قد يضطر لتنزيل ملف 27B بحجم 16,464,440,224 بايت (نحو 15.3 GiB)، وقد لا يصبح جهازه مؤهلًا أصلًا. يلزم مسار ترقية يحافظ على نموذج سابق موثوق أو اختيار بديل مناسب؛ لا يجوز تجاوز التحقق الأمني لحل المشكلة.
Removing 4B/9B means verify_install rejects their existing manifests. Previously working users face a 16,464,440,224-byte replacement (about 15.3 GiB) or become ineligible. Provide a supported migration or retained trusted catalog entries; do not bypass verification.

### P2 — التنزيل قد يبدو متوقفًا ويعرض خطأ غير مناسب | Download can appear stuck and mislabel failures
Evidence: provider/artifacts.py:91,100; provider/app.py exception handling.
الاتصال ينتظر حتى 120 ثانية، ولا يبدأ تقدم البايتات قبل أول قراءة بحجم يصل إلى 1 MiB. فشل الاتصال الأول يُعرض كخطأ محرك، وفشل القراءة لاحقًا قد يصبح رسالة عامة. الإلغاء لا يقطع القراءة المحجوبة فورًا. الصورة وحدها لا تحدد هل العائق شبكة أم إصدار قديم أم خطأ آخر.
Connection timeout is 120 seconds and byte progress begins only after the first read of up to 1 MiB. Initial network failures are labeled as runtime failures; subsequent read failures can become generic errors. Cancellation does not immediately interrupt a blocking read. The screenshot cannot establish the underlying network/version cause.

### P2 — روابط وتعليمات الإصدار قديمة | Release guidance is stale
Evidence: README.md:9,22,80,93; WINDOWS_TRIAL.md:9,28.
الروابط تشير إلى 1.1.1، والوثائق تشرح 4B/9B بينما الكتالوج الحالي يحتوي 27B فقط. عدة إصدارات مختلفة تحمل اسم ملف 1.1.3 نفسه، والعنوان داخل التطبيق يعرض 1.1 فقط. هذا يجعل تشخيص جهاز المستخدم ومطابقة الإصدار صعبًا.
Docs link 1.1.1 and describe 4B/9B while the current catalog contains only 27B. Different releases share the same 1.1.3 asset filename and the app title shows only 1.1. Add an exact build identifier and synchronize release guidance.

### P2 قبل تفعيل البحث — مكون غير موصول وحماية تحويلات ناقصة | Before enabling web research
Evidence: provider/app.py chat; provider/web.py:41,66; tests/test_web.py.
دوال البحث موجودة ومختبرة منفردة، لكنها غير موصولة بمحادثة التطبيق. لا تعتبر ميزة مكتملة ولا يوجد دليل أنها ترسل محادثات المستخدم حاليًا. كذلك يتحقق الكود من الرابط الأول ثم يسمح بتحويلات urllib الافتراضية دون إعادة فحص الوجهة؛ ويحدث حل DNS مرة أخرى عند الاتصال. قبل التفعيل يلزم اختيار صريح للمستخدم، وحماية الوجهات والتحويلات، ومعاملة محتوى الصفحات كمصدر غير موثوق.
Web helpers exist and have isolated tests, but desktop chat does not call them. Do not claim working web research or current chat disclosure. Initial URL validation is followed by default urllib redirects without destination revalidation, plus a second DNS resolution at connection time. Before activation require explicit user opt-in, redirect/destination protection, and untrusted-source handling.
