# قاعدة تجربة الاستخدام | User experience rule

المستخدمون الأوائل عرب، ونفترض أقل قدر ممكن من المعرفة التقنية لدى العميل والمزود. يجب أن تكون التجربة أسهل ما يمكن: تنزيل ملف تثبيت واحد، فتحه، ثم إكمال الإعداد من داخل التطبيق. لا نطلب الطرفية أو Python أو أدوات تطوير أو تعديل ملفات أو متغيرات بيئة. العربية افتراضية، والإنجليزية خيار إضافي. اجعل الاختيارات قليلة، والإعدادات الافتراضية مناسبة، والأخطاء مفهومة مع خطوة إصلاح واضحة. تنزيل النماذج والمحرك والتحقق منهما مسؤولية التطبيق. أي مسار يحتاج أوامر أو إعدادات تقنية يُصنّف اختبارًا داخليًا ولا يُقدَّم كتجربة مكتملة للمستخدم. اختبر التثبيت والتحديث والإزالة على Windows دون Python قبل اعتماد الإصدار. لا تصف ملف مصدر أو ZIP بأنه مثبت جاهز.

The first users are Arabic speakers with minimal technical knowledge, whether clients or providers. Optimize for the simplest experience: download one installer, open it, and complete setup inside the app. Do not require terminals, Python, developer tools, file editing or environment variables. Default to Arabic with optional English. Minimize choices, use suitable defaults, and show understandable errors with a clear recovery step. The app owns model/runtime downloads and verification. Any command-based or technical setup path is an internal test, not a completed user experience. Validate install, upgrade and uninstall on Windows without Python before approving a release. Never present source files or a ZIP as a ready installer.
